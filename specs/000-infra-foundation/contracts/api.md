# Contracts: Infrastructure & Foundation

**Feature**: `000-infra-foundation` | **Date**: 2026-03-07

> Infrastructure features expose internal service contracts (interfaces) and
> a single external endpoint (health check). This document defines both.

---

## External Endpoint: Health Check

### GET /healthz

Returns the health status of all infrastructure dependencies.

**Response 200** (all healthy):
```json
{
  "status": "Healthy",
  "checks": {
    "postgresql": { "status": "Healthy", "description": "Database connection validated" },
    "redis": { "status": "Healthy", "description": "PING returned PONG" },
    "hangfire": { "status": "Healthy", "description": "Job storage accessible" }
  },
  "totalDuration": "00:00:00.142"
}
```

**Response 503** (degraded/unhealthy):
```json
{
  "status": "Unhealthy",
  "checks": {
    "postgresql": { "status": "Healthy", "description": "Database connection validated" },
    "redis": { "status": "Unhealthy", "description": "Connection refused" },
    "hangfire": { "status": "Healthy", "description": "Job storage accessible" }
  },
  "totalDuration": "00:00:05.003"
}
```

**Notes**: Uses ASP.NET Core `IHealthChecksBuilder`. Individual checks are registered for PostgreSQL (`Npgsql`), Redis (`StackExchange.Redis`), and Hangfire storage.

## Standard Error Response Contract

All API errors across all features follow this format:
- **Unexpected exceptions**: Enforced by global `ExceptionHandlingMiddleware`
- **Expected business failures**: Produced by `ResultExtensions.ToProblem()` in endpoint code (includes `CorrelationId` from `ICorrelationIdProvider`)

Endpoints MUST use `result.ToProblem(correlationIdProvider)` to convert failed `Result` objects into error responses. Manual construction of `StandardErrorResponse` in endpoints is prohibited.

```json
{
  "type": "string",
  "title": "string",
  "status": 400,
  "errors": {
    "fieldName": ["Error message 1", "Error message 2"]
  },
  "correlationId": "abc-123-def"
}
```

**Notes**: `errors` field is null for non-validation errors. `correlationId` is always present.

### ResultExtensions.ToProblem() — Endpoint Error Helper

```
ResultExtensions (static class)
├── ToProblem(this Result result, ICorrelationIdProvider correlationIdProvider) → ObjectResult
```

- Converts a failed `Result` into an `ObjectResult` containing `StandardErrorResponse`.
- Maps: `Error.Code` → `Type`, `Error.Description` → `Title`, `Error.StatusCode` → `Status`.
- Sets `CorrelationId` from `correlationIdProvider.CorrelationId` (generated by `CorrelationIdMiddleware`).
- Sets `ObjectResult.StatusCode` from `result.Error.StatusCode`.
- Throws `InvalidOperationException` if called on a successful result.
- Location: `Shared/ResultExtensions.cs`.

**Usage in endpoints**:
```csharp
if (result.IsSuccess)
    return Ok(result.Value);

return result.ToProblem(correlationIdProvider);
```

## Internal Service Contracts

### ITenantProvider

Scoped service providing the current organization context.

```
ITenantProvider
├── CurrentOrganizationId: Guid? (get)
```

- HTTP context: resolved from JWT `organizationId` claim.
- Hangfire context: set by job parameters.
- Null when no tenant context exists (e.g., registration endpoints).

### ICorrelationIdProvider

Scoped service providing the current request/job correlation ID.

```
ICorrelationIdProvider
├── CorrelationId: string (get, set)
```

- HTTP context: set by `CorrelationIdMiddleware` (from `X-Correlation-Id` header or generated).
- Hangfire context: generated per job by `IServerFilter`.

### ILLMService

Provider-agnostic text generation abstraction (OpenAI API standard).

```
ILLMService
├── CompleteAsync(LLMRequest request, CancellationToken ct) → LLMResponse
├── CompleteWithJsonAsync<T>(LLMRequest request, CancellationToken ct) → LLMResponse
```

- Default implementation: `OpenAiLLMService` using typed `HttpClient`.
- Polly policies: retry (3 attempts, exponential backoff) + circuit-breaker.
- Provider swappable via configuration (any OpenAI-compatible endpoint).

### IEmbeddingService

Provider-agnostic vector embedding abstraction (OpenAI API standard).

```
IEmbeddingService
├── EmbedAsync(string text, CancellationToken ct) → float[]
├── EmbedBatchAsync(IReadOnlyList<string> texts, CancellationToken ct) → float[][]
```

- Default implementation: `OpenAiEmbeddingService` (model: `text-embedding-3-small`, 1536 dimensions).
- Polly policies: retry (3 attempts, exponential backoff) + circuit-breaker.
- Provider swappable via configuration.

## Middleware Pipeline Order

The middleware must be registered in this order in `Program.cs`:

```
1. CorrelationIdMiddleware      ← earliest, before auth
2. ExceptionHandlingMiddleware  ← catches all unhandled errors
3. Authentication               ← JWT validation
4. Authorization
5. Routing                      ← Controller endpoints (Partial Controller Pattern)
6. SignalR hub mapping
7. Hangfire dashboard mapping
8. Health check endpoint mapping
```

## Correlation ID Header Contract

| Header | Direction | Behavior |
|--------|-----------|----------|
| `X-Correlation-Id` | Request (incoming) | If present and non-empty, used as-is. If absent, a new GUID is generated. |
| `X-Correlation-Id` | Response (outgoing) | Always present. Contains the resolved or generated correlation ID. |

## SignalR Hub Contract

### Hub Path: `/hubs/notifications`

**On Connection**:
1. Authenticate via JWT (standard ASP.NET Core SignalR auth)
2. Read `organizationId` claim from JWT
3. Add connection to exactly one group: `org:{organizationId}`

**On Disconnect**:
- ASP.NET Core automatically removes the connection from all groups

**Sending Rules**:
- All sends MUST use `Clients.Group($"org:{organizationId}")`
- `Clients.All` is PROHIBITED

**Notes**: The hub itself defines no methods in this phase. Downstream features add their own events (e.g., `SummarizationCompleted`, `ReminderTriggered`). The hub only establishes the tenant-scoped group infrastructure.
